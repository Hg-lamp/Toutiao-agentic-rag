# Personal Mission Agent 产品边界

## 1. 文档状态

- 状态：Implementation baseline
- 适用版本：Mission MVP v1
- 更新时间：2026-09-12
- 规范性关键词：`MUST` 表示必须，`SHOULD` 表示建议，`MAY` 表示可选。

## 2. 产品目标

Personal Mission Agent 让用户通过一句自然语言创建一个有时间、条件、预算和授权边界的生活事务任务。Agent 在授权范围内规划和执行可逆步骤，在不可逆或高风险步骤前暂停并请求用户介入。

第一阶段只验证以下闭环：

```text
自然语言目标
→ 结构化任务
→ 用户确认计划
→ 定时等待
→ 搜索、筛选、比价
→ 准备订单
→ 展示最终摘要
→ 用户确认
→ 提交订单
→ 验证和通知
```

## 3. MVP 范围

### 3.1 支持

- 创建、查看、暂停、恢复、取消和过期任务；
- 解析平台、商品描述、规格、价格上限、时间和默认地址；
- 在允许的平台进行搜索、商品详情读取和价格/库存比较；
- 形成候选商品列表和排序理由；
- 选择候选规格并准备订单；
- 在最终提交前创建 Human-in-the-loop 请求；
- 记录所有状态迁移、动作和用户决定；
- 任务中断后从检查点恢复；
- 同一任务避免重复提交副作用。

### 3.2 明确不支持

- 绕过验证码、人机验证、限购、风控或平台访问控制；
- 读取、推断或保存支付密码、短信验证码或完整银行卡信息；
- 未经用户明确授权的支付或最终下单；
- 自动购买替代商品，除非用户在任务中显式允许；
- 任意宿主机 Shell 执行；
- 默认访问项目外文件、密钥、生产数据库或系统配置；
- 对平台规则不允许的自动化进行规避；
- 将沙盒中成功预演等同于真实世界结果保证。

## 4. 产品原则

1. Agent 负责规划和重复性操作；用户保留最终决定权。
2. LLM 只能提出结构化动作，不能直接越过策略层调用执行器。
3. 所有不可逆动作必须具备明确授权、有效期和参数范围。
4. 外部状态变化必须重新验证，不能复用过期确认。
5. 失败应暂停并解释，而不是静默采取替代方案。
6. 任何任务都必须可取消、可审计、可恢复。

## 5. 成功标准

一个任务只有在外部结果被验证、审计事件已落库、用户收到结果通知后，才可进入 `COMPLETED`。模型输出“已完成”本身不能作为完成证据。
