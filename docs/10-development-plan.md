# 开发计划与验收门槛

## 1. 阶段划分

### Phase 0：协议冻结

交付：

- Task、Action、Policy、Human Request schema；
- 状态迁移表；
- 风险等级和 scope 清单；
- 事件和审计字段；
- 威胁模型；
- 失败场景矩阵。

门槛：所有协议字段有类型、范围、默认值和错误行为。

### Phase 1：任务内核

实现：

- 任务仓储；
- 状态机；
- revision 乐观锁；
- 任务租约；
- Action 注册与策略闸门；
- Human Request 持久化；
- 事件 outbox；
- 暂停、恢复、取消、过期。

门槛：不接真实平台也能用模拟执行器跑通完整生命周期。

### Phase 2：模拟电商

实现：

- 模拟搜索、库存、价格变化；
- 比价和候选选择；
- 订单预览；
- 用户确认；
- 重复提交和未知结果测试；
- 失败恢复和重新规划。

门槛：覆盖价格变化、库存变化、连接断开、重复恢复、过期确认五类场景。

### Phase 3：真实只读能力

只接入搜索、详情、库存和价格查询。禁止真实下单。

门槛：真实平台返回不稳定、登录失效、页面结构变化时都能安全暂停。

### Phase 4：真实订单准备

增加选规格、加购和订单预览。仍禁止自动提交。

门槛：用户看到的预览与执行前重新读取的状态哈希一致。

### Phase 5：人工确认后提交

只支持用户实时确认后的单次提交，不提供自动支付。

门槛：

- 只执行一次；
- 价格或规格变化会重新确认；
- 未知结果不会重试提交；
- 外部订单状态可验证；
- 审计链完整。

## 2. 测试矩阵

### 单元测试

- 状态迁移合法性；
- Action schema；
- 风险和 scope；
- 金额与币种；
- 授权 TTL 和参数哈希；
- 幂等键；
- 脱敏器。

### 集成测试

- 任务仓储 + outbox；
- scheduler + lease；
- Human Request API；
- ToolGateway + SandboxBroker；
- MCP 超时和异常；
- 断线恢复。

### 场景测试

- 用户拒绝后不继续；
- 用户修改预算后重新规划；
- 价格变化重新审批；
- 库存消失不买替代品；
- 验证码转人工；
- 提交超时进入 UNKNOWN；
- 任务取消阻止后续动作；
- 服务重启后不重复下单。

## 3. 发布门槛

发布前 MUST 满足：

1. 所有 R4 路径有人工确认；
2. 核心状态迁移和恢复测试通过；
3. 没有未处理的未知结果自动重试；
4. 审计事件完整；
5. 敏感字段脱敏检查通过；
6. 沙盒安全验收通过；
7. 真实平台适配器有明确的允许域名和平台规则说明；
8. 默认配置为保守模式：不自动支付、不绕过验证、不购买替代品。

## 4. 当前工程映射

现有工具安全能力可复用：

- `backend/services/tool_gateway.py`：工具注册、scope、超时、并发和路由；
- `backend/services/sandbox_broker.py`：MCP 一次性 Docker 沙盒；
- `backend/mcp/server.py`：沙盒内 MCP JSON-RPC；
- `backend/config/tool_config.py`：工具和沙盒运行参数。

Mission 内核应作为独立模块接入，不应把任务状态、审批和电商逻辑直接塞入现有 RAG 图。RAG 可以作为任务规划或证据检索能力，但不能替代确定性状态机和风险闸门。
