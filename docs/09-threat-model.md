# 威胁模型与安全约束

## 1. 保护对象

- 用户身份和登录状态；
- 地址、联系方式和偏好；
- 资金和订单；
- MCP 凭据；
- 任务状态和审计记录；
- 宿主机文件、进程和网络；
- 第三方平台账户信誉。

## 2. 主要威胁

| 威胁 | 防护 |
|---|---|
| Prompt injection | 外部页面内容只作为不可信数据，不能改变系统策略 |
| 越权工具调用 | ToolRegistry + 服务端 scope 校验 |
| 任意命令执行 | 工具白名单、参数 schema、MCP 沙盒 |
| 沙盒逃逸 | 非 root、只读根文件系统、无网络、丢弃 capability、资源限制 |
| 重复下单 | 幂等键、外部状态查询、任务租约 |
| 过期授权复用 | 授权 TTL、单次使用、参数哈希 |
| 敏感信息泄露 | 脱敏日志、最小权限、禁止模型读取凭据 |
| SSRF | 域名允许列表、禁止任意 URL 和内网地址 |
| 恶意适配器 | 注册审核、固定 schema、最小 scope |
| 任务劫持 | user/tenant/task 上下文由服务端注入并校验 |

## 3. 不可信输入

以下全部视为不可信：

- 用户自然语言；
- 网页文本、商品标题和评论；
- MCP 工具返回；
- 浏览器 DOM；
- 外部 API 错误信息；
- 任务恢复时的旧模型输出。

不可信内容不能声明“已获得授权”、不能修改策略、不能生成新的权限 scope。

## 4. 沙盒基线

现有 `SandboxBroker` 的默认基线必须保持：

```text
Docker runtime
--network=none
--read-only
--user=65532:65532
--cap-drop=ALL
--security-opt=no-new-privileges
--pids-limit=128
--memory=512m
--cpus=1
```

MCP 失败时不得回退到宿主机执行。第一阶段如需浏览器运行时，必须建立单独的浏览器沙盒 profile，不得复用任意命令沙盒。

## 5. 安全验收

- 未授权 R4 调用 100% 被拒绝；
- 过期或参数变化的授权 100% 被拒绝；
- 未注册动作 100% 被拒绝；
- 外部页面提示不能改变策略；
- 沙盒不可访问宿主机文件和网络；
- 日志抽样不得出现凭据和完整地址；
- 取消任务后不再启动新的副作用动作。
